# kamc 收尾计划（除 Web 前端外的全部剩余项）

全部验证不使用 kubectl、不触碰真实集群：单测 + 进程内 e2e（假 apiserver/假 IDP）+ Docker PG/Redis（TEST_PG_DSN / TEST_REDIS_ADDR 门控）。每个里程碑一次提交，最后全量回归 + AGENT.md/记忆更新。

## 1. casbin 跨副本策略同步（§7.6）
- 不引第三方 watcher 依赖，自写 ~60 行 Redis pub/sub：`internal/platform/authz/watcher.go`——`authz.New(d, WithSyncChannel(redisCli, channel))`；策略增删后 `PUBLISH am:casbin:changed`，各副本订阅回调执行 `enforcer.LoadPolicy()`（全量重载，规模内足够）。
- 装配：platform runtime 把已有的 revocations Redis 客户端传给 authz；未配置 Redis = 单副本（现状不变）。
- 测试：gated `TEST_REDIS_ADDR`（Docker Redis）双 enforcer 实例——A 加策略 → B 在超时内可见。

## 2. OIDC state 外置 Redis（§4.1）
- `oidc.Client` 抽 `StateStore` 接口（Save / Take 一次性消费用 GETDEL）：内存实现（现有 map 语义，默认）+ Redis 实现（`SET EX 600` / `GETDEL`）。
- 装配：platform runtime 在 Redis 可用时注入 Redis 实现；未配置保持单副本行为。
- 测试：接口级单测（内存实现覆盖 Save/Take/过期语义）；Redis 实现走 gated 测试。

## 3. Agent 401 停止重试（§6.5）
- `DialFunc` 签名改为返回 `(*websocket.Conn, *http.Response, error)`（握手失败时带响应）。
- connectLoop：识别 401 → 记明确日志（"等待管理员重新签发"）→ 进入驻留态（select done / token 变更信号）；`tokenWatch` 检测到 Token 文件哈希变化时发信号，循环恢复重试。
- `Config` 增加 `TokenPollInterval`（默认 30s，测试注入短值）。
- 测试：dial 返回 401 → 尝试次数停止；改写 Token 文件 → 恢复拨号（waitFor 断言）。

## 4. 平台侧隧道读活性看门狗（§6.3）
- wsconn：内置 lastRead 原子时间戳（数据帧在 Read 刷新、ping 帧经 SetPingHandler 刷新并回 pong——尊重 wmu 单写者约束），暴露 `LastActivity()`。
- `Manager` 新增 watchdog 选项（默认检查 25s / 超时 75s = 3×Agent ping + 余量）：`Attach` 起看门狗 goroutine，`time.Since(LastActivity)` 超限 → `closeTunnel` → 既有 monitorSession/Remove/分离钩子链路自动生效。仅对实现 `activityTracker` 的连接启用（wsconn 满足），无追踪器的连接跳过（不盲杀）。
- 测试：注入极短超时 + 永不活跃的连接 → 隧道被回收、Get 报未连接；活跃连接（定期 MarkActivity）不被误杀。

## 5. 审计落库（§12.2）
- `modules.AuditEvent`（timestamp/user/groups/cluster/method/path/verb/allowed/reason/source_ip/latency_ms）。
- `internal/platform/audit`：异步 Writer（缓冲 chan + 批量 insert，done-channel 并发模式）→ PG 不可用时写本地 spill 文件（JSONL），恢复后回放并清空。事件源：Proxy 允许/拒绝（含 latency）、TunnelWS 接入、策略踢出、登录回调成败。
- dao：`SetupAudit` + 批量插入；管理面查询 API `GET /api/v1/audit?user=&cluster=&limit=`（admin 组）。
- 测试：Writer 单测（批量聚合、sink 故障→spill、恢复回放）；e2e（发请求 → 直接查 PG 断言事件字段）。

## 6. Prometheus 指标（§12.3）+ /metrics
- 引入 prometheus client（DefaultRegisterer）；指标：`kamc_requests_total{cluster,user,verb,code}`、`kamc_casbin_denials_total{cluster}`、`kamc_rate_limited_total`、`kamc_proxy_duration_seconds`、`kamc_tunnel_connected_clusters`（gauge，Register/Remove/Release 维护）、`kamc_audit_dropped_total`、`kamc_peer_relay_total{src,dst}`。
- Agent 侧无 HTTP 端口，本轮仅平台侧指标（文档注明）。
- `GET /metrics`（promhttp，无鉴权——仅集群内网约定，文档说明）。
- 测试：/metrics 端点 200 且含 kamc_ 前缀；计数器随请求递增（testutil）。
